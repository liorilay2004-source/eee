# מתחילים כאן: מה לעשות, לפי הסדר

> דף קצר לבעלים, נכון לקוד ב-`main` ב-30.9.2026. בכל צעד: מה עושים, למה, הפקודה המדויקת, ואיך יודעים שזה עבד. הפירוט המלא: [CLOUDFLARE_SETUP.md](CLOUDFLARE_SETUP.md). משהו לא עובד? [סעיף 12: פתרון תקלות](CLOUDFLARE_SETUP.md#12-פתרון-תקלות).

**כללים לכל הדף:**
- מפתח, טוקן או סוד **לעולם לא** בצ'אט, במייל, בקוד או ב-Issue. ל-Cloudflare הוא נכנס רק בשאלה ש-`npx wrangler secret put` שואל. המקום היחיד הנוסף המותר ל-`ACCESS_KEY` הוא מסך הנעילה של האתר (צעד 5.4).
- כל הרשמה לספק: **מסלול חינמי בלבד, בלי כרטיס אשראי. אם מבקשים כרטיס, עוצרים.**
- הודעת שגיאה לא מובנת? לא מנסים לעקוף את השגיאה. עוצרים ושואלים, בלי להדביק מפתחות.
- צריך במחשב: Node.js 22.12 או חדש יותר, git, ומסוף עם bash, curl ו-python3. מצעד 2 והלאה, כל בלוק פקודות מתחיל בתיקיית הריפו וחוזר אליה.

## 1. לעדכן את הקוד במחשב

**למה:** ההעלאה לוקחת את הקוד מהמחשב שלך, וקוד ישן במחשב = גרסה ישנה באוויר. **איפה:** בתיקייה שבה שכפלת את הריפו (ב[סעיף 4](CLOUDFLARE_SETUP.md#4-שלב-א--מיגרציות-למסד-חובה-לפני-ההעלאה) היא נקראת `eee`). אין עותק עדיין? `git clone https://github.com/liorilay2004-source/eee`

```bash
cd eee                            # הנתיב לתיקייה אצלך
git checkout main
git pull
git rev-parse --short=12 HEAD     # 12 התווים של הקומיט: אותם נחפש בצעד 4
```

**עבד אם:** `git pull` מסתיים ב-`Already up to date.` או ברשימת קבצים, בלי `error`, בלי `fatal:` ובלי `CONFLICT`.

## 2. Worker: מיגרציות למסד, ואז העלאה

**למה:** הקוד החדש צריך את הטבלאות החדשות במסד `eee-db`, ולכן קודם המיגרציות ורק אחריהן הקוד.

**בדיקה לפני שמתחילים:** אם `ACCESS_KEY` הוגדר בעבר, העלאת ה-Worker מדליקה את הנעילה לפני שהאתר ב-Pages התעדכן. פותחים https://eee-api.liorilay2004.workers.dev/api/health: אם מופיע `"lockStatus":"on"` (או `misconfigured`), עושים קודם את צעד 3 ורק אחר כך את צעד 2 ([למה](CLOUDFLARE_SETUP.md#6ג-נעילת-האתר-לשימוש-אישי-סוד-אחד-חינם)).

**מריצים את השורות אחת אחת, לא מדביקים את הבלוק כולו.** שאלת המיגרציות היא y/n, ושורה מודבקת שמתחילה ב-`n` (כמו `npx wrangler deploy`) נקראת כ-"no" ושום דבר לא מוחל.

```bash
cd worker
npm ci
npx wrangler d1 migrations apply eee-db --remote   # אם נשאל continue, עונים y
npx wrangler deploy
cd ..
```

- wrangler מבקש להתחבר? `npx wrangler login` (נפתח דפדפן לאישור), ואז מריצים שוב את אותה פקודה. wrangler מריץ רק מיגרציות שעוד לא הוחלו, ולכן בטוח להריץ שוב.
- פרטי הגרסה נכתבים לבד: שלב ה-`[build]` ב-`worker/wrangler.toml` רץ בכל deploy (בפלט: `[custom build] build-info: <קומיט> <זמן>`). אין צעד נוסף.
- ה-Worker מחובר ל-GitHub ([Workers Builds](CLOUDFLARE_SETUP.md#דרך-א--workers-builds-מהדשבורד-בלי-מסוף-מומלץ-אם-אין-מחשב))? אז הקוד כבר עלה לבד עם המיזוג ל-`main`, אבל מיגרציות הוא **לא** מריץ: אותן מריצים בכל מקרה.

**עבד אם:** כל מיגרציה בטבלה מסומנת ✅ (או `✅ No migrations to apply!`), ובפלט של ה-deploy מופיעה הכתובת `https://eee-api.liorilay2004.workers.dev`. פירוט: [סעיף 4](CLOUDFLARE_SETUP.md#4-שלב-א--מיגרציות-למסד-חובה-לפני-ההעלאה) · [סעיף 5, דרך ב'](CLOUDFLARE_SETUP.md#דרך-ב--wrangler-במסוף).

## 3. Web: להעלות את הממשק ל-Pages

**למה:** את Pages מעלים ידנית. בלי הצעד הזה האתר נשאר בגרסה הקודמת (למשל בלי מסך הנעילה של צעד 5). לפי [`web/README.md`](../web/README.md#cloudflare-pages) בונים עם `npm run build` ומעלים את `dist/` עם Wrangler Pages. **שם פרויקט ה-Pages לא כתוב בריפו:** מוצאים אותו בדשבורד, Workers & Pages ← הפרויקט שהכתובת שלו `eee-web-bly.pages.dev`, וכותבים אותו במקום `PROJECT_NAME`:

```bash
cd web
npm ci
npm run build
npx wrangler@4.143.0 pages deploy dist --project-name PROJECT_NAME
cd ..
```

- wrangler לא מותקן בתיקייה `web/`, ולכן `npx` עשוי לשאול אם להתקין אותו (`Ok to proceed?`): עונים y. wrangler שואל אם ליצור פרויקט חדש? **עוצרים (Ctrl+C):** השם לא נכון.

**עבד אם:** מודפס `✨ Deployment complete!`, ובדשבורד, בפרויקט, הפריסה החדשה מסומנת Production. אם היא מסומנת Preview, היא לא באוויר: עוצרים ושואלים.

## 4. בדיקה

**למה:** לוודא שה-Worker והמסד מעודכנים, בלי לנחש (הבדיקה פונה רק ל-Worker; הממשק מאומת בצעד 3, בתווית Production). מריצים מתיקיית הריפו. **בוחרים פקודה אחת** ומריצים רק אותה.

כל עוד האתר לא נעול:


```bash
bash scripts/smoke.sh
```

אחרי הנעילה (צעד 5):

```bash
( read -rs EEE_ACCESS_KEY && export EEE_ACCESS_KEY && bash scripts/smoke.sh )
```

בצורה השנייה המסוף לא מציג כלום: מדביקים את המפתח ולוחצים Enter. המפתח לא נשמר בהיסטוריה ולא מודפס.

**איך קוראים את התוצאה:** שורה לכל בדיקה (בריאות, דילים, לוח מחירים, גילוי יעדים, חיפוש) עם PASS (עבר) או FAIL (נכשל), ובסוף `הכול תקין / all checks passed` או `יש כשלים / some checks FAILED`.
- בשורת הבריאות צריך לראות: `build=` עם 12 התווים מצעד 1, `migration="0006_m11_price_alerts.sql"`, `pending=false`, ו-`lock=off` (אחרי צעד 5: `lock=on`). אותו מידע בדפדפן: https://eee-api.liorilay2004.workers.dev/api/health (פתוח גם כשהאתר נעול, ולעולם לא מראה את המפתח).
- `migrations pending!`: המיגרציות לא הורצו. חוזרים לצעד 2.
- `build` שונה מצעד 1: באוויר גרסה אחרת. חוזרים לצעדים 1–2. סיומת `-dirty` = יש במחשב שינויים שלא נשמרו בקומיט בתיקייה `worker/`.
- לוח מחירים, גילוי יעדים וחיפוש נכשלים עם `HTTP 503 source_unavailable`: אין מקור מחירים. בדרך כלל `TRAVELPAYOUTS_TOKEN` עוד לא הוגדר: הטוקן לוקחים מאתר Travelpayouts (Profile ← API token). ההרשמה שם: **מסלול חינמי בלבד, בלי כרטיס; אם מבקשים כרטיס, עוצרים.** מגדירים אותו (מדביקים רק בשאלה של הפקודה): `npx wrangler secret put TRAVELPAYOUTS_TOKEN` מתוך `worker/` ([סעיף 6](CLOUDFLARE_SETUP.md#6-שלב-ג--סודות-ומשתנים)).
- `HTTP 401`: האתר נעול, מריצים בצורה עם המפתח. `HTTP 429`: יותר מדי בקשות, מחכים כמה דקות ומריצים שוב. פירוט: [בדיקת עשן](CLOUDFLARE_SETUP.md#אחרי-כל-העלאה--בדיקת-עשן) · [סעיף 7](CLOUDFLARE_SETUP.md#7-שלב-ד--אימות-מחליפים-url-בכתובת-שלך).

## 5. נעילה לשימוש אישי (רק אחרי שצעדים 2 ו-3 באוויר ובדיקת העשן עברה)

**מתי להמשיך:** אם שורות הבריאות והדילים במבחן העשן PASS והכשלים היחידים הם `HTTP 503 source_unavailable` (בלי `TRAVELPAYOUTS_TOKEN` שלוש מתוך חמש השורות נכשלות בכוונה). אחרי צעד 3 פותחים את האתר פעם אחת, כדי לוודא שנטענה הגרסה החדשה.

**למה:** בלי נעילה כל אחד יכול להשתמש ב-API. **הסדר חשוב: קודם הקוד, בסוף הסוד.** ממשק ישן לא יודע לבקש מפתח ורק מציג שגיאות. לפני שמתחילים, `/api/health` מראה `"locked":false,"lockStatus":"off"`. אין שם השדות האלה? גרסת Worker ישנה עוד באוויר: חוזרים לצעד 2.

1. יוצרים מפתח אקראי (32 תווים) ושומרים אותו במנהל הסיסמאות:
   ```bash
   node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
   ```
2. **רק עכשיו** מגדירים אותו כסוד. את המפתח מדביקים בשאלה שהפקודה שואלת, לא בשורת הפקודה:
   ```bash
   cd worker
   npx wrangler secret put ACCESS_KEY
   cd ..
   ```
   המפתח נשאר על המסך: מנקים את המסוף (`clear`) לפני שמעתיקים ממנו פלט כלשהו כדי לבקש עזרה.
3. בודקים:
   ```bash
   curl -s https://eee-api.liorilay2004.workers.dev/api/health   # ..."locked":true,"lockStatus":"on"
   curl -i https://eee-api.liorilay2004.workers.dev/api/deals    # HTTP 401 ... "unauthorized"
   ```
4. פותחים את https://eee-web-bly.pages.dev ומדביקים את המפתח במסך הנעילה, **פעם אחת בכל מכשיר ובכל דפדפן**. מעכשיו בדיקת העשן בצורה עם המפתח (צעד 4).

- `"lockStatus":"misconfigured"`: המפתח לא תקין (צריך 20–256 תווים באנגלית, בלי רווחים), והאתר סגור לגמרי. מגדירים מפתח חדש מהמחולל שבשלב 1.
- **החלפת מפתח:** מריצים שוב `npx wrangler secret put ACCESS_KEY` (מתוך `worker/`) עם מפתח חדש. כל מכשיר יבקש את החדש. אם יש לך את תוסף הדפדפן, מעדכנים גם בו מיד.
- **ביטול הנעילה:** `npx wrangler secret delete ACCESS_KEY` (מתוך `worker/`). האתר חוזר מיד להיות פתוח לכולם.
- **יציאה ממכשיר:** בתחתית כל עמוד, "יציאה (מחיקת המפתח מהמכשיר)". פירוט: [סעיף 6ג](CLOUDFLARE_SETUP.md#6ג-נעילת-האתר-לשימוש-אישי-סוד-אחד-חינם).

## 6. רשות: מקורות מחיר נוספים

**למה:** Travelpayouts נותן מחירים שמורים (בני יומיים עד שבוע). מקור נוסף נותן **מחיר חי** לעד 4 זוגות התאריכים הזולים בכל חיפוש חדש ומלא (לא בתשובה שנשלפה מהמטמון), וכך מאשר שהמחיר עוד עומד, ואנחנו לא תלויים בספק אחד. **ההמלצה: להתחיל בלי אף אחד** ([סעיף 13](CLOUDFLARE_SETUP.md#13-החלטות-שלך)). אם כן: אחד בכל פעם, Ignav קודם. **סיכון ב-Ignav:** מקור הנתונים שלו לא מתועד, ורשימה של צד שלישי טוענת שהוא קורא את Google Flights (לא אומת). לפי מסמך המחקר, לפני שנשענים עליו שואלים אותו על זכויות מטמון והצגה ([FLIGHT_API_RESEARCH.md](FLIGHT_API_RESEARCH.md#5-scraping-serp-and-data-as-a-service)).

| ספק | הסוד | הרשמה (מסלול חינמי, בלי כרטיס) | חינם אצל הספק | התקרה בקוד שלנו |
|---|---|---|---|---|
| Ignav | `IGNAV_API_KEY` | https://ignav.com/pricing | 1,000 בקשות, פעם אחת (לא מתחדש) | 800 בסך הכול, עד 27 ביום |
| SerpApi | `SERPAPI_KEY` | https://serpapi.com/pricing | 250 חיפושים בחודש | 100 בחודש (UTC), עד 4 ביום |
| SearchApi | `SEARCHAPI_KEY` | https://www.searchapi.io/pricing | 100 בקשות, פעם אחת | 50 בסך הכול, עד 2 ביום |
| Wego | `WEGO_API_TOKEN` | https://developers.wego.com/docs/affiliate/get-started | אין מכסה חינמית מתועדת, רק מפתח בדיקה זמני (עד שבועיים, באישור ידני) | 30 בסך הכול, 1 ביום |

**Wego רק אם קיבלת מפתח בדיקה בחינם.** לפי מה שפורסם (לא אומת), גישה קבועה אצלם עולה כסף: לא משלמים. כשמגיעים לתקרה המקור פשוט נעצר, והחיפוש ממשיך בלעדיו.

**הפעלה של ספק אחד:**
1. נרשמים במסלול החינמי. **אם מבקשים כרטיס, עוצרים.**
2. מגדירים את המפתח (מדביקים אותו רק בשאלה של הפקודה). במפתח הזה לא משתמשים בשום מקום אחר, גם לא בלוח הניסויים באתר הספק:
   ```bash
   cd worker
   npx wrangler secret put IGNAV_API_KEY      # או SERPAPI_KEY / SEARCHAPI_KEY / WEGO_API_TOKEN
   cd ..
   ```
3. מחפשים טיסה באתר. תנאים: `TRAVELPAYOUTS_TOKEN` מוגדר ובדיקת העשן עוברת; מחפשים מסלול ותאריכים שלא חיפשו לאחרונה (תשובה מהמטמון לא קוראת לאף מקור חי); מחפשים לנוסע בוגר אחד, כי צעד 4 משווה לנוסע אחד. **עבד אם:** ב"על הנתונים של החיפוש הזה" הספק מופיע עם "N מחירים"; בלוח הבקרה של הספק המונה עלה ואתה עדיין במסלול החינמי; והמונה `used` שלו עלה אצלנו (מתוך `worker/`, קריאה בלבד): `npx wrangler d1 execute eee-db --remote --command "SELECT source, period, used FROM source_quota"`
4. **בדיקת מחיר ידנית, לפני שמשאירים אותו פעיל:** לוקחים מתשובת החיפוש כרטיס שה-`source` שלו הוא הספק הזה (בדפדפן: F12 ← Network ← הבקשה `search` ← לשונית Response). פותחים ב-Google Flights את אותו מסלול ואותם תאריכים, לנוסע בוגר אחד במחלקת תיירים, ומשווים מחיר ומטבע למחיר **הכולל הלוך-חזור** לנוסע אחד. הפרש של יותר מכמה אחוזים, או שהספק מציג רק הלוך או מחיר לקבוצה: מסירים את הסוד (`npx wrangler secret delete IGNAV_API_KEY`, או השם של הספק, מתוך `worker/`) ומדווחים. **מדווחים רק מחיר, מטבע, תאריכים ו-`source` מלשונית Response.** אף פעם לא "Copy as cURL", לא כותרות הבקשה ולא צילום של Headers: אחרי צעד 5 הבקשה נושאת `Authorization: Bearer <ACCESS_KEY>`. עד הבדיקה, המחיר של הספק הוא הנחה ולא עובדה.
5. רק אז עוברים לספק הבא.

- **ב-SerpApi לעולם לא מפעילים "Automatic Early Renewal".**
- **SerpApi ו-SearchApi קוראים את Google Flights.** תנאי השימוש של Google אוסרים גישה אוטומטית, ו-Google תבעה את SerpApi (התביעה לא הוכרעה, לפי [§13](FLIGHT_API_RESEARCH.md#13-decisions-taken-owner-delegated-them-on-2026-09-29-you-decide)). זה מה שהמקורות אומרים, לא ייעוץ משפטי: **ההחלטה שלך**. בלי מפתח הם כבויים ([FLIGHT_API_RESEARCH.md, §14](FLIGHT_API_RESEARCH.md#14-owner-rule-nothing-may-cost-money-free-allowances-only-up-to-the-allowance-2026-09-29), [§5](FLIGHT_API_RESEARCH.md#5-scraping-serp-and-data-as-a-service)). פירוט: [סעיף 6א](CLOUDFLARE_SETUP.md#6א-מקורות-מחיר-חיים-אופציונלי-חינם-בלבד).

## 7. רשות: עוד שלוש הגדרות

- **קוד שותף בקישורי ההזמנה:** `npx wrangler secret put TRAVELPAYOUTS_MARKER` (מתוך `worker/`). [סעיף 6](CLOUDFLARE_SETUP.md#6-שלב-ג--סודות-ומשתנים).
- **התראות מחיר בטלגרם (חינם):** שלושה ערכים: הסודות `TELEGRAM_BOT_TOKEN` ו-`TELEGRAM_WEBHOOK_SECRET`, והשם `TELEGRAM_BOT_USERNAME` (לא סוד, נכנס ל-`worker/wrangler.toml` תחת `[vars]`), ועוד רישום webhook חד-פעמי מול טלגרם. **שינוי ב-`wrangler.toml` חייב להיכנס לקומיט ב-`main`** (עריכה מקומית בלי קומיט מסמנת את הגרסה `-dirty`, וההעלאה הבאה מ-`main` תמחק אותה), או שמבקשים מהמפתח לעשות אותו. **אזהרה:** בסעיף 6ב טוקן הבוט וסוד ה-webhook נכתבים בשורת פקודה (curl) ונשמרים בהיסטוריית המסוף: לא מבצעים את החלק הזה לבד, מבקשים מהמפתח. [סעיף 6ב](CLOUDFLARE_SETUP.md#6ב-התראות-מחיר-בטלגרם-אופציונלי-חינם).
- **Workers Logs (שורת `match_audit` על כל חיפוש):** כבוי. מדליקים בבלוק `[observability]` ב-`worker/wrangler.toml` ו-deploy (גם זה חייב קומיט ל-`main`, או שמבקשים מהמפתח). המכסה החינמית לא אומתה כאן: לפני שמדליקים, מוודאים בדשבורד שאין שום חיוב. [סעיף 14](CLOUDFLARE_SETUP.md#14-workers-logs-optional).

## 8. מה קורה לבד (אין מה לעשות)

- **כל שעה (בדקה 43, UTC):** נסרק מסלול אחד מתוך 24, כך שכל מסלול נסרק פעם ביום, והמחירים נשמרים כהיסטוריה. עובד רק כש-`TRAVELPAYOUTS_TOKEN` מוגדר.
- **עמוד "מבצעים":** מחיר מסומן כמבצע רק מול היסטוריה של **אותם תאריכים**: לפחות 12 בדיקות (בדיקות שנעשו באותו חלון של 6 שעות ב-UTC, 00–06, 06–12, 12–18 או 18–24, נספרות כאחת), על פני 7 ימים לפחות, ובחמישה ימים שונים לפחות. מהסריקה השעתית לבד זה לוקח לפחות 12 ימים לכל מסלול, כי היא בודקת כל מסלול פעם ביום; חיפושים של אותו מסלול מוסיפים בדיקות. עד אז המסלול מסומן "אוספים היסטוריה" עם פסי התקדמות, וזה צפוי. (הספים: `worker/src/deals.ts`)
- **כל יום ב-03:17 UTC (בערך 05:17–06:17 בישראל):** ניקוי של מחירי טיסות שעברו, יומן חיפושים ישן, מטמון ומונה קצב. מוני המכסות של הספקים לא נמחקים.
- **כל שעה (בדקה 29, UTC):** בדיקת התראות המחיר, כל התראה בערך פעם ביום. עובד רק אחרי הגדרת טלגרם (צעד 7); עד אז רק נמחקות התראות שפג תוקפן.
